# Аудит безопасности и надёжности

Это инженерная проверка текущей реализации, а не формальная сертификация.
Пункты с приоритетом P0 нужно закрыть до публикации прямого listener или Unix
socket в недоверенной среде.

## Результаты

### P0 — возможное повреждение памяти в Nginx worker — исправлено в рабочем дереве

`nginx-module/ngx_http_httpfin_module.c` собирает JSON размером 4096 байт через
непроверяемые `ngx_cpymem()`. Функция сериализации строки может остановиться у
границы буфера, но вызывающий код не узнаёт об усечении и продолжает записывать
префиксы полей и закрывающий suffix. Длинные URI, Host или User-Agent могут
записать данные за пределами stack buffer и уронить worker.

Теперь используется bounded builder: он проверяет каждую операцию и возвращает
`oversize` до выхода за границу. Перед выпуском всё равно нужна реальная сборка
модуля из исходников Nginx и container smoke test.

### P0/P1 — неограниченная map ClientHello — исправлено в рабочем дереве

`internal/tlsinspect.Observer` сохраняет Hello для каждого ClientHello и удаляет
запись только после HTTP-запроса. Оборванные handshakes остаются в map. Поток
незавершённых handshakes может бесконечно увеличивать память.

Добавлены TTL, жёсткий лимит и удаление устаревших записей. Очистка строго по
событию закрытия соединения ограничена возможностями Go TLS callback API.

### P1 — нет таймаутов HTTP/TLS — исправлено в рабочем дереве

Оба Go-сервера запускаются без read/write/header/idle timeout и ограничения
размера headers. Медленный клиент может надолго удерживать goroutine и sockets.

Оба listener теперь используют read, write, header, idle timeout и
`MaxHeaderBytes`.

### P1 — spoofing событий через Unix socket — открытый риск

Socket получает права `0666`. Любой локальный процесс с доступом к пути может
подделывать события или заполнять очередь. Нужны защищённый runtime-каталог,
отдельная группа, права `0660`, проверка версии события и лимитов полей.

### P1 — нет reconnect после перезапуска Go — открытый риск

Nginx worker подключается к datagram socket один раз. После перезапуска Go
создаётся новый socket, но старый worker сам к нему не подключается. События
теряются до reload Nginx или добавления reconnect-логики.

### P2 — тихая остановка ingest — открытый риск

При ошибке чтения datagram goroutine завершается, а HTTP-сервис продолжает
считаться healthy. Нужны логирование и отдельный ingest health signal.

### P2 — неэффективное bounded-хранилище — открытый риск

Лимит в 5000 записей есть, но добавление в начало slice копирует весь массив.
При большом RPS лучше использовать ring buffer. Размеры пользовательских полей
тоже нужно ограничивать до сохранения.

### P2 — неполное завершение — открытый риск

`log.Fatal` завершает процесс сразу и обходится без deferred cleanup. Нужен
signal-driven shutdown для HTTP-серверов, TLS listener и Unix socket.

### P2 — неполная совместимость ResponseWriter — открытый риск

Logging wrappers не сохраняют дополнительные интерфейсы вроде `Flusher` и
`Hijacker`. Это может повлиять на streaming и protocol upgrade, хотя текущие
UI и API их не требуют.
