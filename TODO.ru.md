# План httpfin после версии 0.2

Основной рабочий путь версии 0.2 готов: сбор наблюдений, JSON API, текстовый
отчёт, HTML status-page, TLS/HTTP-режимы, Docker smoke-сценарий и документация.

## Ближайшие приоритеты

### Высокий

- [ ] Провести нагрузочное тестирование Nginx-модуля и пути через
  Unix-датаграммы: пропускная способность, переполнение, остановленный или
  медленный сборщик, восстановление и влияние на задержку запросов.
  Container smoke уже проверяет ограниченную нагрузку, остановленный сборщик и
  восстановление хранения; полноценное stress-тестирование и характеристика
  переполнения ещё впереди.
- [ ] Добавить в события Nginx upstream-контекст: адрес и статус upstream,
  время connect/header/response, размер запроса и сведения о retry, если
  соответствующие переменные Nginx доступны.
- [ ] Добавить семантическое сравнение двух сохранённых отчётов. Сравнивать
  нормализованные наблюдения, а не HTML/TXT: клиента, User-Agent, профиль,
  TLS, ALPN, SNI, route, статус, время, размер, upstream-контекст и точку
  наблюдения. Добавить контрактные тесты отчёта для `go-http`, `go-tls`,
  `nginx-http-module` и отсутствующих полей.
- [ ] Добавить небольшую CLI-команду или API-операцию для сравнения двух
  экспортированных JSON-снимков с ненулевым результатом при расхождении
  выбранных полей.

### Средний

- [ ] Добавить метрики коллектора для Prometheus: `received`, `decoded`,
  `stored`, `dropped`, ошибки handoff, число записей в store, uptime и состояние
  ingest.
- [ ] Сохранять `traceparent` и `tracestate` как ограниченные поля корреляции;
  не считать их секретами и не использовать как labels метрик.
- [ ] Добавить явные allowlist и redaction policy для выбранных request- и
  response-заголовков. Body capture оставить выключенным по умолчанию и
  ограничивать длину значений до хранения и экспорта.
- [ ] Добавить фильтры отчёта по диапазону времени, route, классу статуса,
  источнику клиента, точке наблюдения и correlation ID.

## Сознательно отложено

SQLite или другое постоянное хранилище истории, автоматическое обновление
профилей, body capture, распределённое хранилище, WAF-решения, anti-bot,
raw TLS capture и fingerprinting соединения HTTP/2 не входят в ближайший план.
Возвращаться к ним стоит только при появлении конкретной эксплуатационной
потребности.

## Текущие ограничения

- Nginx HTTP-модуль работает после TLS termination и не видит исходный
  ClientHello или HTTP внутри TLS passthrough.
- Unix datagram работает в режиме best effort: событие может потеряться, а
  запрос клиента всё равно будет обслужен.
- User-Agent и профиль можно подделать; это не доказательство личности клиента.
  JA3/JA4 и поля HTTP/2, если их передал внешний источник, имеют то же
  ограничение.
- Динамический модуль Nginx должен соответствовать версии Nginx и libc.
