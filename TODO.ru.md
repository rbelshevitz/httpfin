# План httpfin

Цель — давать понятные доказательства о пути HTTP/TLS-запроса. Отпечаток и
антибот-сигнал остаются вспомогательными признаками, а не единственной причиной
блокировки.

## Готово

- [x] Рабочие конфигурации Nginx: завершение TLS, `stream ssl_preread`,
  совместимость модуля и Docker-сборка.
- [x] Ограниченный буфер наблюдений в памяти.
- [x] Профили настольных, мобильных браузеров и WebView.
- [x] Отчёт с клиентами, изменениями отпечатка, сигналом бота, состоянием
  данных, точкой наблюдения и маскированием секретов.
- [x] Безопасный режим наблюдения, аварийное отключение и примеры Fail2ban.
- [x] Раздельные режимы Docker для smoke-тестов и host/systemd для эксплуатации.
- [x] Передача Nginx-событий через профиль, baseline, policy и security-log.
- [x] Тесты интеграции, случайных входов, перезапуска сокета и гонок данных.
- [x] Документация для эксплуатации и ручной проверки QA.

## Ближайшие задачи для текущей эксплуатации

- [ ] **Fail2ban на хосте:** на отдельном тестовом адресе проверить четыре
  состояния — журнал без jail не блокирует, фильтр не принимает `observe`,
  включённый jail блокирует только `deny`, `unban` снимает блокировку. Проверить
  IPv4, IPv6, trusted proxy и allowlist.
- [ ] **Потери событий:** согласовать минимальные состояния `получено → разобрано
  → сохранено → отброшено`, вывести их в health/служебную проверку и описать,
  как сверять их с access log. Не считать отсутствие метрики доказательством
  отсутствия запроса.
- [ ] **Надёжность:** добавить проверяемые сценарии для неверных прав на socket,
  переполнения datagram и медленного Go-приёмника. Во всех трёх случаях Nginx
  должен продолжать обслуживать запросы, а причина потери должна быть видна
  оператору.

## Дальние пункты — не брать в текущую работу

- [ ] Долговременная история в SQLite — только если понадобится поиск после
  перезапуска; не включать по умолчанию.
- [ ] Блокировка по совпадению fingerprint: потребуется отдельный TLS-aware edge
  proxy, wire observer или прямой Go TLS proxy. Текущий HTTP-модуль Nginx для
  этого недостаточен.
- [ ] Автоматическое обновление профилей и распределённое хранилище.

## Ограничения

- HTTP-модуль Nginx не видит passthrough и не разбирает ClientHello.
- Unix-сокет передаёт события с возможной потерей; для полного аудита нужны
  журнал доступа или будущее долговременное хранилище.
- Динамический модуль должен быть собран под ту же версию Nginx и ту же системную
  библиотеку C.
